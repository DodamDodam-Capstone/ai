## 2. 프롬프트 수정 과정 (개발셋, qwen3:8b)

한 번에 하나씩 바꾸고 매번 개발셋으로 점수를 쟀다. 개발셋·시험셋 문장은 프롬프트 예시로 쓰지 않았다.

| 단계 | 내용 |
|---|---|
| 기준 점수 | 처음 프롬프트 (v0) |
| 1단계 | category 정의와 판정 순서 (기준서 2·3장) |
| 2단계 | topic 추출 규칙 (기준서 4-1~4-3), few-shot의 짧은 동의 예시 교체 |
| (검증기) | 사람 이름 검사 추가 (반려동물 이름·호칭 제외) |
| 3단계 (C) | key_point 규칙 (동행 관계 포함, 이름 금지), few-shot에 동행 예시. 3회 모두 이름 때문에만 실패하면 이름을 가려 저장 |
| A 시도 | 3단계에서 few-shot 변경만 되돌림 → category가 0.9 근처로 돌아오지 않아 채택하지 않음 |
| 건강/일상 경계 시도 | 수면·운동이 일상보다 우선한다는 한 줄 추가 → 아래 참고, 채택하지 않음 |

**건강/일상 경계 수정 시도**: 결합 F1은 0.800 → 0.824로 올랐으나, 사전에 정한 기준(결합 정답 수 +2)을 충족하지 못해 채택하지 않음 (결합 정답 28 → 28. E08은 맞게 됐고 E12는 틀리게 됨). 결합 F1 상승은 정답에 없는 topic이 줄어든 효과다.

**최종 프롬프트는 C.** 추가 수정은 하지 않는다.

## 3. 채점 규칙 변경 (시험셋 평가 전, 2026-11-27)

**바꾼 이유**: 개발셋 C 결과에서 정답과 내용·category가 모두 맞는데 topic 이름 표현만 달라 오답 처리된 사례가 6개 있었다 (E03, E10, E15, E21, E27, E28). 이름 일치만으로는 "주제를 찾았는가"를 잴 수 없었다.

**새 규칙** (topic/eval.py에 명시, 시험셋 평가 전 고정)
1. 1:1 짝짓기. 이름(정규화: 띄어쓰기 앞 조사 "의"와 띄어쓰기 제거)이 정답 이름·aliases와 같으면 먼저 짝짓는다.
2. 남은 것끼리 근거 turn IoU(교집합/합집합) 0.5 이상인 쌍을 IoU가 큰 순서로 짝짓는다. 0.5는 라벨러 비교 도구와 같은 정의·기준값이다.
3. 주 지표는 결합 F1 (짝이 맞고 category도 맞은 것). 이전 방식 지표도 함께 보고한다.
4. 실패 세션은 예측 없음으로 채점(0점)하고 실패율을 따로 보고한다.

정답(aliases 포함)은 모델 결과를 본 뒤 고치지 않았다.

## 6. 알려진 한계

### 6-1. 이름 검사 오탐 (결정: 그대로 두고 기록, 시험셋 재실행 안 함)

- 검증기의 사람 이름 검사는 "두 글자 + 이 + 조사" 꼴을 이름으로 본다. 형용사·동사 활용("~이는")과 일반 명사+조사("~이랑")도 같은 꼴이라 오탐이 생긴다.
- 시험셋 아이 발화 기준 이름 후보 4건 중 **오탐 2건** (T008, T026), 실제 이름 2건 (T027, T093). 반려동물 이름은 제외됐다.
- **실제 피해는 qwen T008 1세션**: 3회 모두 오탐으로 거부되어 이름 가리기가 적용됐고, key_point 문장이 훼손됐다 (활용어 일부가 "친구"로 바뀜). Gemini T008은 2차 시도에서 다른 표현을 써서 통과했다 (호출 1회 추가). T026은 출력에 해당 말이 나오지 않아 영향 없음.
- 규칙은 시험셋 평가 전에 고정했으므로 그대로 두었다. 시험셋을 보고 검증기를 고치면 시험셋에 맞추는 셈이기 때문이다.
- 환각 라벨링에서 qwen T008은 `note`에 "검증기 이름 가리기로 생긴 훼손"으로 표시하고 유형별 집계에서 따로 센다.
- **향후 과제**: 이름 검사 패턴 개선 (활용어 제외, 형태소 분석기 사용 검토). 개선 후에는 새 시험셋으로 확인한다.

### 6-2. 그 밖의 한계

- 시험셋 정답은 LLM이 만들고 사람은 경계 사례만 검수했다. 모델과 같은 방향으로 틀린 정답이 있으면 점수가 높게 나올 수 있다.
- 기준서 v1.2의 일부 규칙(D15–D19)은 시험셋 검토 과정에서 보완됐다. 프롬프트에는 규칙만 넣고 시험셋 문장은 쓰지 않았다.
- 개발셋이 작아(정답 33개) topic 1개 차이가 약 3%p다. 개발셋에서 1개 차이는 우연과 구분하지 않았다.
- qwen3:8b는 프롬프트가 조금만 바뀌어도 경계 사례(E08, E30 등)의 판단이 바뀌었다.

## 7. 향후 과제

- 표준 topic 목록으로 이름 통일 (대시보드 담당과 필요성 논의)
- 근거 turn을 주제 시작부터 끝까지 포함하도록 하는 지시 (제품 개선, 이번 평가에서는 넣지 않음)
- 이름 검사 오탐 개선 (6-1)
- sentiment 기준서 작성과 재라벨링
- `with_whom` 필드 (대시보드 담당 확인 후)
