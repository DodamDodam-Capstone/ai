## 0. 설계서의 category 체계

- **목적**: 분류 자체가 아니라 **보호자 대시보드의 주간·월간 통계와 검색·필터링**. 세션 요약만 하려면 category는 필요 없다.
- **구조**: Category = 통계용 고정 라벨 10개 / Subtopic = 보류(null) / Topic = 실제 대화에서 뽑는 구체적 주제.
- **10개를 고른 근거는 설계서에 없다.** 설계서 스스로 "대분류 Skeleton"이라고 부르고, 각 category에 예시 키워드 2–3개만 있다. 정의·경계는 이 문서에서 정한다. 개수와 enum 값은 유지한다 (M1).

| Category | 설계서 예시 키워드 |
|---|---|
| `SCHOOL_LEARNING` 학교·학습 | 수업 · 숙제 · 선생님 |
| `FRIENDS_RELATIONSHIP` 친구·관계 | 친구 · 우정 · 다툼 |
| `FAMILY` 가족 | 부모 · 형제 · 가족 활동 |
| `PLAY_GAME` 놀이·게임 | 장난감 · 보드게임 |
| `HOBBY_CREATIVE` 취미·창작 | 그림 · 만들기 · 음악 |
| `ANIMAL_NATURE` 동물·자연 | 강아지 · 공룡 · 식물 |
| `DAILY_LIFE` 일상생활 | 음식 · 여행 · 하루 일과 |
| `HEALTH_BODY` 건강·신체 | 운동 · 수면 · 신체 |
| `KNOWLEDGE_CURIOSITY` 지식·호기심 | 과학 · 우주 · 기술 질문 |
| `OTHER` 기타 | 근거 부족 · 분류 어려움 ← **이 문서에서 뜻을 바꿈 (D6)** |

> **설계서와 다른 점 (설계서 수정 필요)**
> 1. `OTHER`: 설계서는 "근거 부족·분류 어려움"이지만, v1은 **"내용은 분명한데 10개 어디에도 맞지 않는 주제"**만 `OTHER`로 한다. 근거가 부족하면 topic을 만들지 않는다 (D6).
> 2. `FAMILY`: 설계서 예시 키워드 "가족 활동"을 **"가족이 중심인 일"**로 좁힌다. 가족과 함께한 활동은 활동 쪽으로 분류한다 (D3). 설계서의 예시 표("할머니 집 갔어 = 일상생활")와는 일치한다.

## 1. 대원칙

1. **장소가 아니라 대화의 내용으로 판정한다.** 학교에서 있었던 일이라도 내용이 친구 관계면 친구, 식물 키우기면 자연이다.
2. **키워드가 아니라 아이가 말하려는 중심으로 판정한다.** "자동차"라는 단어가 나와도 장난감 놀이면 놀이, 직접 만들고 싶다면 창작, 작동 원리를 물으면 지식·호기심이다. 책·영상도 그 **내용**이 중심이면 내용으로 판정한다 (2-4).
3. **category는 "무엇을 했나 / 무엇에 대한 이야기인가"로 정한다. "누구와, 어디서"는 category를 정하지 않는다.** 함께한 사람은 key_point에 관계 유형으로 남긴다 (4-4). `with_whom` 필드는 추가 예정, 미확정 (M3).
4. **아이가 자기 말로 내용을 말한 것만 topic이 된다.** 짧은 대답·맞장구뿐이면 topic을 만들지 않는다 (4-1, D5·D6).
5. **하나의 topic에는 category 하나.** 여러 개에 걸치면 아래 2장의 판정 순서에서 먼저 해당하는 것을 고른다.

## 2. 판정 순서 (위에서부터 처음 해당하는 것)

| 순서 | 질문 | Category |
|---|---|---|
| 1 | 원리·사실을 **궁금해하거나 알고 있는 것을 이야기하는가?** (**학교 수업·교육에서 배운 내용은 7번**, 단 아이가 스스로 "왜?"·"어떻게?"를 물으면 1번, D15. **동물·식물·자연에 대해 아는 사실**(이름·생김새·특징·사는 곳 등)은 4번으로. 단 동물·자연에 대한 "왜?"·원리는 1번, D9) | `KNOWLEDGE_CURIOSITY` |
| 2 | 특정 **사람 자체, 그 사람과의 관계, 그 사람에게 일어난 일**이 중심인가? (다툼, 놀림, 우정, 탄생, 생일, 혼남, 그리움) **사람이 함께 등장하기만 한 활동은 해당하지 않는다** → 2-1 '사람 바꿔 보기' | 친구·또래 → `FRIENDS_RELATIONSHIP` / 가족 → `FAMILY` |
| 3 | 몸·건강·병원·수면·운동인가? (운동 = 태권도·수영·줄넘기 같은 신체 단련, 축구·피구·달리기 시합 같은 **규칙 있는 스포츠**. 술래잡기·숨바꼭질·미끄럼틀 같은 **놀이는 6번**, D18. 춤·무용은 5번, D17) | `HEALTH_BODY` |
| 4 | 동물·식물·자연을 **직접 경험했거나, 그것에 대한 관심·좋아함·아는 것을 이야기하는가?** (눈·모래·물 등이 놀이·만들기의 **재료**로만 쓰였으면 해당하지 않음. 바다·산·캠핑장 등이 **여행·나들이 장소**일 뿐이면 해당하지 않음: 동물·자연 자체가 이야기의 중심일 때만, D16) | `ANIMAL_NATURE` |
| 5 | **결과물을 만들었거나 만들고 싶다고 말하는가?** 또는 그리기·악기·노래·**춤·무용** 등 표현 활동, 배우는 예체능 취미인가? (디지털 게임 안에서 만든 것 포함) → 2-3 | `HOBBY_CREATIVE` |
| 6 | 장난감·게임·놀이를 **하고 즐긴** 이야기인가? (캐릭터·만화 이야기도 잠정적으로 여기, D14) | `PLAY_GAME` |
| 7 | **학습 활동 자체**인가? (공부, 수업 시간, 숙제, 시험, 선생님, 1–6에 해당하지 않는 교과·교육 내용) | `SCHOOL_LEARNING` |
| 8 | 식사·하루 일과·외출·방문·여행·집안일인가? 또는 **갖고 싶은 것·선물, 용돈·저금, 이사** 같은 생활 속 일인가? (D19. 내용 없는 시청·독서도 잠정적으로 여기, 2-4) | `DAILY_LIFE` |
| 9 | **내용은 분명한데** 1–8 어디에도 해당하지 않는가? | `OTHER` |

> - `OTHER`는 "판단이 어려울 때"가 아니다. 두 category 사이에서 애매하면 이 순서대로 고르고, 정답 라벨링에서는 허용 대안(M2)으로 처리한다. 근거가 부족하면 `OTHER`가 아니라 topic을 만들지 않는다.
> - 이 순서를 현재 정답 35개에 적용하면 아래 세 곳을 빼고 모두 현재 정답과 같다 (작성자 확인. 재라벨링에서 독립 검증 필요).
>   - **E10 마인크래프트**: `PLAY_GAME` → `HOBBY_CREATIVE`, 허용 대안 `PLAY_GAME` (2-3) — 정답 반영 완료
>   - **E05 강아지, E14 우주**: 짧은 동의뿐이라 topic 삭제 (4-1) — 정답 반영 완료

### 2-1. 사람 바꿔 보기 (2번 판정용)

함께한 사람을 다른 사람으로 바꿔도 이야기가 그대로 성립하면 그 사람은 **동행**이고 활동이 중심이다. 바꾸면 성립하지 않으면 **그 사람이 중심**이다.

| 아이 발화 | 바꿔도 성립? | 결과 (topic / category / key_point에 남길 사람) |
|---|---|---|
| "학교에서 친구랑 카드게임하고 놀았어" | 성립 (동생으로 바꿔도 같음) | 카드게임 / `PLAY_GAME` / 친구 |
| "민수가 반칙해서 싸웠어. 속상해" | 성립 안 함 | 친구와의 다툼 / `FRIENDS_RELATIONSHIP` |
| "주말에 할머니 집 가서 김치전 먹었어" (E20) | 성립 | 할머니 댁 방문 / `DAILY_LIFE` / 할머니 |
| "할머니 보고 싶었는데 만나서 좋았어" | 성립 안 함 | 할머니 / `FAMILY` |
| "엄마아빠랑 놀러갔어! 엄마아빠가 아이스크림 사주셨어" | 성립 (이모로 바꿔도 같음) | 나들이 / `DAILY_LIFE` / 엄마아빠 |
| "아빠가 회사 때문에 바빴는데 오늘은 같이 놀아줘서 너무 좋았어" | 성립 안 함 (아빠와 보낸 시간 자체가 이야기) | 아빠와 보낸 시간 / `FAMILY` |
| "지우랑 그네 탔어. 지우는 제일 친한 친구야. 지우랑 노는 게 제일 좋아" (E02) | 성립 안 함 ("제일 친한 친구"는 그 사람에 대한 말) | 친한 친구 / `FRIENDS_RELATIONSHIP` |

- 한 세션에서 **활동과 사람 이야기를 둘 다 충분히 했으면 topic 2개**로 나눈다. 예: 카드게임(`PLAY_GAME`) + 친구와의 다툼(`FRIENDS_RELATIONSHIP`).
- E02는 놀이와 친구 이야기가 섞인 경계 사례다. 재라벨링에서 두 라벨러가 갈리는지 확인한다.

### 2-2. 학교를 7번에 둔 이유 (대원칙 1과의 관계)

`SCHOOL_LEARNING`을 "학교라는 장소"가 아니라 "학습 활동이라는 내용"으로 정의한다. 학교에서 한 일이라도 내용이 관계·건강·자연·창작·놀이면 그쪽이 먼저 잡히고, 어디에도 속하지 않는 학습 활동만 학교로 온다.
- "학교에서 강낭콩 심었어"(E29) → 4번 `ANIMAL_NATURE`
- "운동회 달리기"(E17) → 3번 `HEALTH_BODY`
- "학교에서 친구랑 카드게임" → 6번 `PLAY_GAME`
- "소방관이 와서 대피 방법 배웠어"(E15) → 1–6에 해당 없음 → 7번 `SCHOOL_LEARNING`

### 2-3. 창작 vs 놀이: "만들면 창작" (M1, D13)

- **결과물을 만들었거나 만들고 싶다고 말하면 `HOBBY_CREATIVE`, 활동 자체를 하고 즐긴 이야기면 `PLAY_GAME`.** 설계서의 자동차 예시("직접 만들고 싶어 → 취미·창작")와 같은 논리다.
- **예외 없이 적용한다.** 디지털 게임, 레고, 요리, 눈 놀이 모두 같은 규칙이다.

| 아이 발화 | 결과 | 이유 |
|---|---|---|
| "자동차 장난감으로 경주 시켰어" (E04) | `PLAY_GAME` | 활동 자체를 즐김 |
| "슬라임 새로 샀어. 말랑말랑해. 재밌어" (E26) | `PLAY_GAME` | 갖고 논 이야기 |
| "슬라임 만들었어" / "슬라임 만들고 싶어" | `HOBBY_CREATIVE` | 결과물을 만듦 / 만들고 싶음 |
| "마크 하는 거 좋아해" | `PLAY_GAME` | 게임을 즐김 |
| "마인크래프트에서 다이아몬드로 큰 집 지었어" (E10) | `HOBBY_CREATIVE` | 게임 안에서 만든 결과물 |
| "자동차 직접 만들고 싶어" (설계서 예시) | `HOBBY_CREATIVE` | 만들고 싶음 |
| "레고로 집 만들었어" | `HOBBY_CREATIVE` | 결과물을 만듦 |
| "엄마랑 김밥 만들었어" | `HOBBY_CREATIVE` | 결과물을 만듦 (엄마는 동행 → key_point) |
| "눈사람 만들었어" | `HOBBY_CREATIVE` | 결과물을 만듦 (눈은 재료일 뿐, 자연 아님) |
| "눈싸움했어" | `PLAY_GAME` | 활동 자체를 즐김 (눈은 재료일 뿐, 자연 아님) |
| "블록 쌓았다가 무너뜨렸어" | `PLAY_GAME` | 쌓기·무너뜨리기 자체를 즐김 |

### 2-4. 시청·독서 (D12, M1)

1. **내용 우선**: 책·영상의 **내용**이 이야기의 중심이면 그 내용의 category로 보낸다.
   - 공룡 책 이야기 → `ANIMAL_NATURE`
   - 과학 영상에서 본 원리 이야기 → `KNOWLEDGE_CURIOSITY`
   - 게임 영상 시청 → 내용이 게임이므로 `PLAY_GAME` (영상 속에서 남이 만든 것을 본 이야기라도, 아이가 직접 만든 것이 아니므로 창작으로 보내지 않는다)
2. **내용 없이 시청·독서 행위 자체만 말한 경우** ("유튜브 봤어", "책 읽었어") → **잠정적으로 `DAILY_LIFE`.** `HOBBY_CREATIVE`에 넣지 않는다 (피아노 연습과 유튜브 시청이 같은 막대로 집계되어 부모가 궁금해할 정보가 가려짐).
3. **라벨링 표시**: 시청·독서·캐릭터가 관련된 topic에는 category와 별개로 `"media": true`를 남긴다. (eval.py는 모르는 키를 무시하므로 정답 파일에 바로 넣어도 된다.)
   - 위 공룡 책 예시는 공룡에 대해 아는 것·좋아함을 말한 경우다. 책에서 본 "왜?"·원리를 이야기하면 1번 `KNOWLEDGE_CURIOSITY` (D9).
4. **캐릭터·만화** (포켓몬, 티니핑 등, D14): 캐릭터 자체가 내용이라 1번 '내용 우선'으로 갈 곳이 없다. **잠정적으로 `PLAY_GAME`**에 넣고 `"media": true`를 표시한다.
5. 시험셋에서 비중이 크면 별도 category 신설을 제안한다. 이때는 enum이 바뀌므로 백엔드·대시보드 담당과 합의한다.

## 3. Category 정의

각 항목의 "포함"은 현재 정답 라벨, "오답"은 모델이 다르게 낸 경우다.

### `SCHOOL_LEARNING` 학교·학습
- **정의**: 학습 활동 자체. 공부, 수업 시간, 숙제, 시험, 선생님, 그리고 다른 category에 속하지 않는 교과·교육 내용(안전 교육 포함). 수업·교육에서 **배운 사실을 전하는** 이야기도 여기(교통안전 교육에서 배운 길 건너는 법). 단 아이가 스스로 "왜?"를 물으면 지식·호기심(D15). **장소(학교)로 판정하지 않는다.**
- **포함**: 받아쓰기(E01), 수학 수업(E11), 새 담임 선생님(E25), 소방 안전 교육(E15)
- **제외**: 학교에서 만난 친구 → 친구(E25 짝꿍) / 수업 시간에 심은 강낭콩 → 자연(E29) / 운동회 달리기 → 건강(E17) / 학교에서 한 카드게임 → 놀이 / 급식 메뉴 → 일상(E26 버섯)
- **오답**: qwen이 짝꿍·달리기·강낭콩을 학교 쪽이나 다른 쪽으로 보냄 → 대원칙 1(장소 아님)

### `FRIENDS_RELATIONSHIP` 친구·관계
- **정의**: 친구·또래 **자체 또는 그들과의 관계** (우정, 다툼, 놀림, 짝꿍, 친구에 대한 생각).
- **포함**: 친한 친구(E02), 친구의 놀림(E16), 짝꿍(E25)
- **제외**: 친구는 함께 했을 뿐이고 활동이 중심인 경우 → 활동 쪽 (친구랑 카드게임 → `PLAY_GAME`, key_point에 "친구와"). 판정은 2-1.

### `FAMILY` 가족
- **정의**: 가족 구성원 **자체, 가족과의 관계, 가족에게 일어난 일** (동생 탄생, 형제 다툼, 생일, 혼남, 그리움, 함께 보낸 시간 자체).
- **포함**: 아기 동생(E03), 형과의 다툼(E18), 엄마 생일(E24), 엄마에게 혼남(E27)
- **제외**: 가족은 함께 갔을 뿐이고 활동이 중심인 경우 → 활동 쪽 (E20 할머니 댁 방문 → `DAILY_LIFE`, E30 바다 여행 → `DAILY_LIFE`, 엄마랑 김밥 만들기 → `HOBBY_CREATIVE`; key_point에 관계 유형)

### `HOBBY_CREATIVE` 취미·창작
- **정의**: 결과물을 만들었거나 만들고 싶다고 말한 활동(디지털 게임 안에서 만든 것, 레고, 요리, 눈사람 포함), 그리기·종이접기·악기·노래·**춤·무용(발레 등)** 같은 표현 활동, 배우는 예체능 취미(운동 제외, D17).
- **포함**: 피아노(E09), 종이접기(E18), 그림 그리기(E22), 마인크래프트 집 짓기(E10)
- **제외**: 운동(태권도·수영) → 건강 / 내용 없는 시청·독서 → 잠정 일상(2-4) / 만든 것 없이 놀이 자체를 즐김 → 놀이

### `PLAY_GAME` 놀이·게임
- **정의**: 장난감, 게임, 놀이를 **하고 즐긴** 이야기. 만든 결과물이 중심이면 창작(2-3). 친구·가족과 함께 노는 것도 포함(2-1). 캐릭터·만화 이야기도 잠정적으로 포함하고 `media` 표시(2-4, D14). 술래잡기·숨바꼭질·미끄럼틀처럼 **규칙 있는 스포츠가 아닌 몸 놀이**도 여기(D18).
- **포함**: 자동차 장난감(E04), 슬라임 갖고 놀기(E26), 눈싸움, 블록 쌓고 무너뜨리기, 게임 영상 시청(2-4), 포켓몬·티니핑 등 캐릭터 이야기(잠정, D14)
- **경계**: E10(마인크래프트)은 `HOBBY_CREATIVE`, 허용 대안 `PLAY_GAME` (2-3, M2).

### `ANIMAL_NATURE` 동물·자연
- **정의**: 동물, 식물, 자연을 **직접 경험한 일**(보기·돌보기·키우기 등), 또는 그것에 대한 **관심·좋아함·아는 것**을 이야기한 것. 동물·자연을 다룬 책·영상의 내용 이야기도 포함(2-4). 눈·모래·물·나뭇잎 등이 놀이·만들기의 **재료**로만 쓰였으면 해당하지 않는다 (눈사람 → 창작, 눈싸움 → 놀이). 바다·산·캠핑장이 **여행·나들이 장소**일 뿐이면 해당하지 않는다 (바다 여행·캠핑 → 일상, 동물원에서 기린을 자세히 본 이야기 → 자연, D16).
- **포함**: 고양이(E06), 강아지 산책(E12), 강낭콩 키우기(E29)
- **제외**: 자연 현상의 원리·이유를 묻거나 설명하는 대화 → 지식·호기심(E21 하늘 색깔, D9)
- **1번과의 경계 (v1.1)**: 동물·자연에 대해 **아는 사실**(이름·생김새·특징·사는 곳)은 여기. "왜?"·원리는 1번 지식·호기심. 예: "티라노는 고기 먹어" → 자연 / "티라노는 왜 팔이 짧아?" → 지식·호기심
- **오답**: 강아지 산책을 qwen이 일상으로 분류 → 판정 순서 4가 8보다 먼저

### `DAILY_LIFE` 일상생활
- **정의**: 식사, 하루 일과, 외출·방문·여행, 집안일, 그리고 갖고 싶은 것·선물, 용돈·저금, 이사 같은 생활 속 일(D19). 여행지가 바다·산이어도 여행이 중심이면 여기(D16). 가족·친구와 함께한 외출·방문도 여기(가족 자체가 중심이면 `FAMILY`). 내용 없는 시청·독서도 잠정적으로 여기(2-4).
- **포함**: 떡볶이(E02), 피자(E06), 할머니 댁 방문(E20), 버섯 급식(E26), 아침 일과(E28), 바다 여행(E30)
- **제외**: 수면 → 건강 / 반려동물과의 일 → 자연 / 음식을 직접 만든 이야기 → 창작(2-3)

### `HEALTH_BODY` 건강·몸
- **정의**: 아프거나 다친 일, 병원, 몸 상태, 수면, 운동. 운동은 신체 단련(태권도·수영·줄넘기)과 규칙 있는 스포츠(축구·피구·달리기 시합). 춤·무용은 창작(D17), 술래잡기 같은 놀이는 놀이(D18). (설계서 예시 키워드: 운동·수면·신체)
- **포함**: 감기(E07), 수면(E08), 달리기(E17), 수영(E23)
- **오답**: 수면은 두 모델 모두 일상으로, 수영은 qwen이 일상으로, 달리기는 qwen이 학교로 보냄 → 프롬프트에 정의가 없어서 생긴 오류. 프롬프트에 명시한다.

### `KNOWLEDGE_CURIOSITY` 지식·호기심
- **정의**: 아이가 원리·사실을 **궁금해하거나, 알고 있는 것을 이야기하는** 대화. 동물·자연에 대한 "왜?" 질문과 원리 이야기 포함(D9). 단 동물·식물·자연에 대해 **아는 사실**("티라노는 고기 먹어", "고양이는 생선 좋아해")은 `ANIMAL_NATURE`. 과학 책·영상에서 본 원리 이야기 포함(2-4). 학교 수업·교육에서 배운 내용을 전하면 학교, 단 수업 중이라도 아이가 스스로 "왜?"를 물으면 여기(D15).
- **포함**: 전기차 원리(E05), 하늘 색깔(E21). (E14 우주는 짧은 동의뿐이라 정답에서 삭제함)
- **오답**: 수학 수업을 qwen이 지식으로 분류 → "수업 과제는 학교"

### `OTHER` 기타
- **정의**: **내용은 분명한데** 1–8 어디에도 해당하지 않는 주제만.
- **아닌 것**: 근거 부족(짧은 대답·맞장구) → topic을 만들지 않는다 / 두 category 사이에서 애매함 → 판정 순서대로 고르고 정답에는 허용 대안(M2)
- **포함**: 장래희망(E19), 꿈속 이야기
- **아닌 것 (v1.2)**: 갖고 싶은 것·선물, 용돈·저금, 이사 → 일상(D19)
- **오답**: 장래희망을 qwen이 취미로 분류

## 4. Topic 판정 규칙

### 4-1. 무엇을 topic으로 뽑나
1. **아이가 그 대상에 대해 자기 말로 내용을 말한 경우**에만 topic으로 뽑는다.
2. **근거가 부족하면 topic을 만들지 않는다** (D5·D6). `OTHER`로 보내지도 않는다.
   - 아이 발화가 "응", "어", "네", "맞아", "좋아", "몰라", "음.." 같은 짧은 대답·맞장구뿐인 경우. AI가 꺼낸 주제라도, 아이가 그 대상에 대해 자기 말을 보태지 않았으면 topic이 아니다.
   - E05 강아지: AI "강아지도 좋아해?" → 아이 "응" → **topic 없음** (정답에서 삭제함)
   - E14 우주: AI가 우주 이야기 → 아이 "응", "응" → **topic 없음** (정답에서 삭제함, E14는 topic 0개)
   - E22 그림: AI "그림 그리는 거 좋아해?" → 아이 "응" + "공주 그림 많이 그려. 그림 그리는 게 제일 좋아. 어제도 세 장 그렸어" → **topic 있음** (AI가 꺼냈어도 아이가 자기 말로 내용을 말함)
3. 다음도 topic이 아니다.
   - 지나가는 언급: "밥 먹으러 갈래" 같은 대화 마무리 (Gemini E14 "식사")
   - 대화의 틀 자체: "선생님한테 말했어", "아빠랑 계획했어" (qwen E16 "교사와의 대화", E24 "아빠와의 계획")
   - 대화 전체를 묶는 너무 넓은 이름: "학교 생활"(Gemini E17), "학습 경험"(qwen E15), "규칙적인 생활"(qwen E28)
   - 함께한 사람만 따로 떼어낸 것: "친구랑 카드게임"에서 "친구"를 별도 topic으로 내지 않는다 (사람 자체를 이야기했을 때만 topic, 2-1).
   - 대상 없이 감정만 말한 것: "오늘 그냥 슬펐어" (D10). 감정의 원인이 있으면 원인이 topic이다 (E03 동생, E08 잠, E27 혼남).

### 4-2. 하나의 topic은 어디까지인가
1. **중심 대상이나 사건 하나가 topic 하나다.** 그 대상의 세부 내용은 별도 topic이 아니라 key_point에 넣는다.
   - 받아쓰기 ⊃ 받침 (qwen E01)
   - 전기차 ⊃ 배터리 위치 (qwen E05)
   - 감기 ⊃ 병원 (qwen E07)
   - 피아노 ⊃ 발표회 (qwen E09)
   - 수면 ⊃ 혼자 자는 것 (qwen E08)
   - 엄마에게 혼남 ⊃ 방 청소 (qwen E27)
   - 바다 여행 ⊃ 조개 줍기 (qwen E30)
2. **같은 대상이 세션 안에서 다시 나오면 같은 topic**으로 묶고 turn_ids를 합친다 (E06 고양이, E26 슬라임).
3. **같은 대상을 두 topic으로 중복해서 내지 않는다** (qwen E05 강아지 2개).
4. 서로 다른 대상이면 나눈다 (E18 종이접기 / 형과의 다툼, E25 새 선생님 / 짝꿍). 활동과 사람 이야기를 둘 다 충분히 했으면 나눈다 (2-1).

> qwen이 topic을 47개(정답 35개) 낸 원인은 대부분 4-1, 4-2 위반이다.

### 4-3. Topic 이름 짓기
1. **짧은 명사구** (대략 2–8자). 문장이나 설명은 쓰지 않는다.
2. **대상이 중심이면 대상 이름**: 고양이, 피아노, 마인크래프트.
3. **사건이 중심이면 "대상 + 사건"**: 친구의 놀림, 형과의 다툼, 엄마에게 혼남.
4. **상위 사건과 세부 대상이 있으면 상위 사건** (D11): 할머니 댁 방문(김치전 아님), 바다 여행(조개 줍기 아님).
5. **표준 표현으로 정규화**: 마크 → 마인크래프트, STT 오인식 수항 → 수학.
6. **사람 이름은 쓰지 않는다**: 지우 → 친구 (qwen E02 key_point에 이름이 남은 사례 있음).
7. 같은 의미의 여러 표현(하늘 색깔 / 하늘과 노을의 색, 아침 일과 / 아침 일상)은 이름 규칙만으로 다 맞출 수 없다. 평가에서는 정답의 aliases로 처리한다 (재라벨링 때 보강).

### 4-4. key_point에 함께한 사람 남기기

`with_whom` 필드가 확정되기 전까지 함께한 사람 정보는 key_point에만 남는다. 빠지면 정보가 완전히 사라지므로:
1. 아이가 함께한 사람을 말했다면 key_point에 **관계 유형**을 반드시 포함한다.
   - 예: "엄마아빠와 놀러 가서 아이스크림을 먹었다고 말함", "친구와 카드게임을 해서 이겼다고 말함", "엄마와 김밥을 만들었다고 말함"
2. 사람 이름은 쓰지 않고 관계 유형만 쓴다.
3. 근거는 아동 발화로 제한한다. AI가 제안하거나 물은 것만으로는 쓰지 않는다.

> 이 규칙은 프롬프트 변경이 필요하다. 다른 변경과 섞지 않고 따로 반영해 점수를 확인한다.

## 5. 결정 사항

### 5-0. 상위 결정

#### M1. 카테고리를 통합·재정의할 것인가 — **확정: 통합하지 않는다**
- 10개 개수와 enum 값은 유지하고, 경계 규칙과 정의를 고친다.
- 점검 기준 (이후 재검토 때도 사용)
  1. **부모에게 쓸모 있는가**: 대시보드에서 이 구분을 보고 부모가 알게 되는 것이 있는가.
  2. **서로 겹치지 않는가**: 경계 쟁점이 몰린 곳은 합치거나 정의를 다시 쓴다.
  3. **빠진 영역이 없는가**: 흔한 주제가 `OTHER`로 빠지지 않아야 한다.
  4. **한쪽에 쏠리지 않는가**: 시험셋 분포를 점검 자료로 쓴다.
- `PLAY_GAME` ↔ `HOBBY_CREATIVE`: 합치지 않고 "만들면 창작" 규칙(2-3). 합치면 부모 리포트에서 "놀이"와 "창작"을 구분할 수 없어 기준 1에서 잃는 것이 더 크다.
- 시청·독서: `HOBBY_CREATIVE`에 넣지 않고 내용 우선 + 잠정 `DAILY_LIFE` + `media` 표시(2-4). 시험셋 분포를 보고 별도 category 신설 여부를 판단한다.
- 모델 정확도만 보고 정하지 않는다. M2의 허용 대안 비율이 특정 쌍에 몰리면 그 경계를 우선 재검토한다.
- 이번 변경(판정 순서·정의·규칙)은 enum·`session_topics` 저장 형식에 영향이 없다. category 신설·통합 시에만 백엔드·대시보드 담당과 합의한다.

#### M2. 평가 때 허용 대안 라벨을 둘 것인가 — **확정: 둔다**
- 정답에 주 라벨 1개와, 경계 사례에 한해 허용 대안 라벨을 최대 1개 둔다. 예: E10 → 재라벨링 결과에 따라 결정.
- 점수 보고
  - **엄격 정확도(주 라벨만)를 주 지표**로, 허용 정확도를 보조 지표로 함께 보고한다.
  - **허용 대안이 붙은 문항의 비율과 그 쌍의 분포**를 함께 보고한다. 비율이 높으면(예: 20~30% 이상) category 정의의 문제로 보고 M1에 반영한다.
  - **두 라벨러 간 일치도(Cohen's kappa)**를 보고한다. 표본이 작으면 불안정하므로 시험셋까지 합친 전체 기준으로 계산하고 **참고용 수치**임을 명시한다.
- 조건 (**예외 없음**)
  - 두 라벨러의 판단이 갈렸거나, 기준서에 경계로 명시된 경우에만 둔다.
  - 모델 결과를 본 뒤에는 추가하지 않는다.
- eval_set.json에 `category_alt` 필드를 추가하고 eval.py를 수정한다 (승인 후).

#### M3. '함께한 사람' 보조 필드 — **추가 예정, 미확정**
- `with_whom` 필드는 **대시보드 담당 확인 전까지 보류**한다. 스키마·검증기·프롬프트에 아직 넣지 않는다.
- 그동안 함께한 사람은 key_point에 관계 유형으로 남긴다 (4-4).
- 확인 후 채택하면 아래 명세를 적용한다.
  - 이름: `with_whom` (`with`는 SQL·Python 예약어라 쓸 수 없다).
  - 값: `FRIEND` · `FAMILY` · `TEACHER` · `ALONE` · `UNKNOWN` 중 복수 선택. 형제자매는 `FAMILY`. `ALONE`은 아이가 명시했을 때만, 언급이 없으면 `UNKNOWN`. 근거는 아동 발화로 제한. 사람 이름은 넣지 않음.
  - 학원 선생님·이웃 어른 등 그 밖의 어른을 어디에 넣을지는 채택 시 정한다.
- 설계서에 명시할 것: 가족·친구 정보는 현재 key_point 문장에만 남고 통계로는 집계되지 않는다. D3·D7(활동 중심 분류)을 택한 데 따른 의도된 선택이다.

## 6. 진행 순서

1. ~~M2 정책 확정~~ (v1 완료)
2. ~~M1 규칙, D 항목 결정, 기준서 v1 확정~~ (v1 완료)
3. **두 라벨러가 v1로 독립 라벨링한다.** (양식: `labeling/conversations.md`, `labeling/label_template.csv`) 모델 결과는 보지 않는다. 시청·독서·캐릭터 관련 topic에는 `"media": true`를 표시한다. E05·E10·E14도 이때 다른 문항과 똑같이 정한다.
4. **판단이 갈린 문항·기준서상 경계 문항에 허용 대안 라벨을 붙이고, kappa를 계산한다.** (`labeling/compare_labels.py`. eval.py는 `category_alt`를 지원하도록 수정 완료) 불일치 사례는 기준서 규칙으로 추가한다 (v1.x).
5. **시험셋**(팀원 작성, 20–30세션)에 다음을 반드시 넣는다: 시청·독서, 캐릭터·만화(D14), D13 사례(레고·김밥·눈사람·눈싸움·블록), 가족 나들이, 친구랑 놀이, 짧은 동의만 있는 주제, 대상 없는 감정. 시험셋 분포를 보고 시청·독서·캐릭터 category 신설 여부를 판단한다.
6. **대시보드 담당에게 함께한 사람 집계 기능 계획을 확인하고**, `with_whom` 채택 여부와 (필요 시) category 신설을 백엔드·대시보드 담당과 한 번에 합의한다.
7. **설계서 수정 요청**: `OTHER` 설명(D6), `FAMILY`의 "가족 활동"(D3), 가족·친구 정보가 통계에 집계되지 않는다는 점(M3).
8. **프롬프트에 반영한다** (승인 후, 한 번에 하나씩: category 정의·판정 순서 → topic 규칙(짧은 동의 포함, few-shot 축구 교체) → key_point 규칙). 변경마다 개발셋 점수를 기록한다.
9. **sentiment 기준서를 별도로 만든다** (neutral vs unknown, 감정 표현만 있을 때, mixed 사용 조건. 짧은 동의는 topic 자체가 없어지므로 sentiment 규칙에서 빠짐).
